# 搜尋提交與空結果狀態設計

## Goal

讓站內搜尋改為使用者按下 Enter 後才執行，並在沒有符合內容時顯示符合 Figma `3452:962` 的完整空結果狀態。

## Scope

- 將首頁、商品列表、生活提案與文章內頁的搜尋行為統一改為提交式搜尋。
- 保留目前每一頁以 `[data-search-item]` 標記內容的搜尋範圍。
- 輸入關鍵字時不隱藏、不篩選任何頁面內容。
- 按下 Enter 後才計算符合項目。
- 有結果時顯示該頁符合項目，隱藏不符合項目。
- 無結果時隱藏原本的主要內容，顯示保留 Header 與 Footer 的完整空結果狀態。
- 使用 Figma 既有空狀態文案、24px 字級、16px 間距、480px 桌面寬度與 `#454545` 文字色。
- 保留搜尋面板的開啟、關閉、焦點與 Escape 鍵操作。

## Out of Scope

- 不建立跨四個頁面的全站搜尋索引。
- 不新增 `search.html` 或新的路由。
- 不新增搜尋結果卡片版型、模糊搜尋、搜尋建議或歷史紀錄。
- 不新增第三方套件或改變既有網站架構。
- 不修改輪播、行動版選單、導覽列或卡片互動。

## Interaction Flow

1. 使用者按 Header 的 Search 開啟搜尋面板。
2. 使用者輸入文字時，頁面內容維持原狀。
3. 使用者按 Enter：
   - 空白關鍵字不執行搜尋，面板保持開啟並維持輸入焦點。
   - 找到項目時，關閉搜尋面板、顯示符合項目並隱藏其他項目。
   - 找不到項目時，關閉搜尋面板、恢復所有搜尋項目的隱藏狀態，隱藏原本主內容並顯示完整空結果狀態。
4. 使用者可從結果或空結果狀態再次開啟 Search 並重新提交。
5. 使用者未提交就按 Escape 或關閉按鈕時，不改變上一次已提交的頁面狀態。

## Structure

- 在四個 HTML 頁面各加入一個預設隱藏的空結果主要內容區域，沿用既有 Header、Footer 與設計 token。
- 在搜尋面板加入表單語意，以 `submit` 事件統一處理 Enter。
- 在 `js/main.js` 分離「比對項目」、「切換一般結果」與「切換空結果」三項職責。
- 在現有 CSS 檔案加入空結果版型與響應式規則，不更動現有元件尺寸。

## Accessibility and Error Handling

- 搜尋以表單提交，避免依賴 `input` 即時事件。
- 空白輸入不清空或改變目前結果。
- 搜尋摘要維持 `aria-live="polite"`，提交後更新符合數量。
- 空結果主要內容使用標題關聯，並確保同一時間只有一個可見的 `main`。
- 關閉面板後將焦點返回 Search；空結果狀態仍可再次開啟搜尋。

## Acceptance Criteria

- 輸入任意關鍵字但尚未按 Enter 時，所有 `[data-search-item]` 的可見狀態不變。
- 按 Enter 後才更新搜尋結果。
- 有符合項目時只顯示符合項目。
- 沒有符合項目時顯示 Figma 空結果文案，且 Header、Footer 仍存在。
- Escape 與關閉按鈕不會觸發搜尋或清除已提交結果。
- 四個 HTML 頁面的搜尋行為一致。
- 不新增 dependency，且現有輪播與行動版選單行為不受影響。

## Test Plan

- 先以瀏覽器重現現況：輸入即時篩選，作為失敗基線。
- 桌面與行動寬度驗證「輸入但未提交」不改變內容。
- 分別驗證有結果、無結果、空白輸入、Escape、關閉與重新搜尋。
- 驗證四個 HTML 頁面皆可提交搜尋。
- 驗證首頁輪播與行動版選單仍正常。
- 執行 `node --check js/main.js`。
- 專案沒有 `package.json`；`npm ci`、`npm run lint`、`npm run test`、`npm run build` 不適用，改以靜態檔案與瀏覽器互動檢查作為完成門檻。
